# Зерно — крипто-аналитика

Дашборд и Telegram-бот, которые собирают котировки из **FreeCryptoAPI**, считают
метрики сами и просят **локальную LLM в Ollama** написать по этим числам спокойный
разбор на русском. Интерфейс свёрстан по макету `Зерно · крипто-аналитика.dc.html`
на дизайн-системе Organic (`frontend/vendor/organic.css` — копия исходного
`styles.css` дизайн-системы, все цвета/отступы/радиусы берутся из её токенов).

```
браузер ─┐                            ┌── FreeCryptoAPI (котировки, свечи, F&G)
         ├── backend/app.py (Flask) ──┤
Telegram ┘        │   SQLite          └── Ollama (локальная модель, разборы)
  бот             └── кэш котировок, кэш разборов, списки, контекст
```

## Что умеет

* **Список наблюдения** до 25 тикеров, у веб-интерфейса и у каждого чата в Telegram — свой.
* **Метрики без LLM**: изменение за сутки и неделю, дневная волатильность,
  уровень риска, характер движения, спарклайн, сводка по всей выборке.
* **Разбор от локальной модели**: короткая строка на карточке, сводка по портфелю,
  «что за» / «что против» по каждому токену. Модель получает только посчитанные
  числа и обязана вернуть JSON по схеме.
* **Два вида дашборда из макета**: «грядка карточек» и «один крупно».
* **Telegram-бот** как второй интерфейс: сводка, разбор по тикеру, добавление и
  удаление токенов, индекс страха и жадности, ежедневный дайджест.
* **Рыночный контекст**: любой текст, присланный или пересланный боту, оседает в
  базе и уходит в модель вместе с числами. То же поле есть в веб-интерфейсе.
* **Демо-режим**: без ключа FreeCryptoAPI сервис поднимается на синтетических,
  но правдоподобных данных — интерфейс и бот полностью рабочие.
* **Запас прочности**: если Ollama недоступна или ответила мусором, текст
  собирается по правилам, и в интерфейсе честно написано, что это не модель.

## Установка

```bash
cd ~/zerno-crypto
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # или системный python
cp .env.example .env        # заполнить ключи
./run.sh web                # http://127.0.0.1:5310
./run.sh bot                # в отдельном терминале
./run.sh prod               # тот же бэкенд под waitress
```

Ollama должна быть поднята локально (`ollama serve`) и модель скачана:

```bash
ollama pull deepseek-r1:latest
```

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `FCA_API_KEY` | ключ FreeCryptoAPI из панели. Пусто → демо-режим |
| `FCA_DEMO` | `1` — принудительно демо-данные даже при наличии ключа |
| `CACHE_TTL_QUOTES` / `_OHLC` / `_FG` / `_LIST` | TTL кэша ответов провайдера, секунды |
| `SPARK_DAYS` | сколько дневных свечей тянуть на график (по свече = 1 кредит) |
| `ENABLE_TECHNICAL`, `ENABLE_NEWS` | дорогие эндпоинты (10 кредитов), по умолчанию выкл. |
| `OLLAMA_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT`, `OLLAMA_NUM_CTX` | локальная модель |
| `CACHE_TTL_ANALYSIS` | TTL кэша разборов (плюс сброс при заметном изменении цифр) |
| `DEFAULT_WATCHLIST` | чем наполняется пустой список |
| `BOT_API_TOKEN` | общий секрет: с ним бот получает доступ к областям `tg:*` |
| `TELEGRAM_BOT_TOKEN`, `API_BASE`, `TELEGRAM_ALLOWED_CHATS` | бот |

## Особенности живого FreeCryptoAPI

Проверено на реальном ключе — три вещи, из-за которых наивная интеграция молча
возвращает пустоту:

1. **Разделитель тикеров — пробел.** `getData?symbol=BTC ETH` (на проводе
   `BTC+ETH`) работает, а закодированный `%2B` даёт `{"status":"success","symbols":[]}`
   без всякой ошибки. Поэтому в `freecrypto.py` тикеры склеиваются пробелом.
2. **Часть монет есть только как биржевая пара.** `LINK` провайдер не знает,
   `LINKUSDT@binance` — знает. Клиент сам подбирает имя: сначала короткий тикер,
   затем `<TICKER>USDT@binance` и `@bybit`; найденное запоминается в кэше.
   Неизвестный тикер в общем запросе обнуляет всю выдачу, поэтому промахи
   добираются по одному.
3. **Бесплатный тариф без истории.** `getOHLC`, `getHistory`, `getFearGreed` и
   технические эндпоинты отвечают `Your plan does not include…` / `No access`.
   Такой отказ запоминается на 6 часов (`cap:<endpoint>`), и сервис переходит на
   собственную историю: каждая котировка пишется в `price_points`, из неё строятся
   график и недельное изменение. Пока точек мало, интерфейс показывает плашку
   «график появится, когда наберётся история», а не рисует ничего выдуманного.
   Недельное изменение появится, когда накопится 8 календарных дней наблюдений.
   Если тариф проапгрейдить, ничего менять не нужно — клиент сам начнёт брать
   историю из API (флаг `capabilities.history` в `/api/snapshot`).

## Кредиты FreeCryptoAPI

Провайдер списывает кредиты за **каждую возвращённую строку**, а не за запрос:
`getData` — 1 за символ, `getOHLC` — 1 за свечу, `getTechnicalAnalysis` — 10,
`getCorrelation`/`getSupportResistance`/`getBollinger` — по 100. Поэтому:

* всё идёт через SQLite-кэш с отдельным TTL на эндпоинт;
* спарклайн стоит `SPARK_DAYS` кредитов на токен и обновляется раз в час;
* дорогие эндпоинты выключены флагами и включаются осознанно;
* если провайдер недоступен, отдаётся просроченный кэш, а не пустой экран.

Полное обновление списка из 6 токенов при пустом кэше — 6 кредитов на текущем
тарифе (только `getData`) или примерно `6 + 6×14 + 1 = 91`, если открыть историю
и индекс страха/жадности.

## API

| Метод | Ручка | Что делает |
| --- | --- | --- |
| GET | `/api/health` | источник данных, состояние Ollama, флаги |
| GET | `/api/snapshot?scope=&refresh=` | рынок + разборы из кэша (модель не запускается) |
| POST | `/api/analysis` | `{kind: portfolio\|token, symbol, force}` — запуск модели |
| GET | `/api/digest?scope=&refresh=` | снимок со сводкой, им пользуется бот |
| GET/POST | `/api/watchlist` | список наблюдения; POST проверяет тикер у провайдера |
| DELETE | `/api/watchlist/<symbol>` | убрать токен |
| GET | `/api/search?q=` | справочник тикеров провайдера |
| GET/POST | `/api/notes` | рыночный контекст |
| DELETE | `/api/notes/<id>` | убрать запись контекста |

`scope=web` — список браузера, `scope=tg:<chat_id>` — список чата; ко второму
пускают только по заголовку `X-Bot-Token`.

## Команды бота

```
/list            сводка по выборке + кнопки по токенам
/t BTC           разбор одного токена (можно просто написать «BTC»)
/add SUI         добавить, /del SUI — убрать
/fg              индекс страха и жадности
/digest on 10    дайджест каждый день около 10:00, /digest off — выключить
/notes /clear    посмотреть и очистить рыночный контекст
```

Любое другое сообщение длиннее десяти знаков (в том числе пересланный пост из
канала) бот сохраняет в рыночный контекст — модель учтёт его в следующем разборе.

## Как устроен разбор

1. `market.build_snapshot` собирает котировки и свечи, считает изменения,
   волатильность, риск, спарклайн и сводку по выборке.
2. `analyst` кладёт эти числа в промпт (плюс индекс страха и жадности,
   при включённых флагах — RSI/MACD и заголовки новостей, плюс рыночный контекст
   из Telegram) и просит модель вернуть JSON по схеме.
3. Результат кэшируется с отпечатком входных данных: изменения огрубляются до
   0.5% (сутки) и 1% (неделя), плюс уровень риска и состав рыночного контекста.
   Абсолютной цены в отпечатке нет намеренно — она шевелится каждые пару минут, и
   вместе с ней разбор переписывался бы на каждом обновлении котировок по 40 секунд
   работы модели на токен. Свежесть добирается TTL (`CACHE_TTL_ANALYSIS`).
4. Локальная модель считает по одному запросу за раз (очередь в `analyst`),
   фронтенд подгружает разборы по одному и показывает заглушки.

Модель нигде не считает цифры сама: все числа в тексте приходят из промпта.
Формулировки о покупке/продаже запрещены в системном промпте, под каждым
разбором стоит «Это наблюдение, а не совет, куда вложить».

## Проверка

```bash
python3 tools/smoke.py          # быстрый прогон всех ручек (секунды)

```

## Скорость

На `deepseek-r1:latest` один разбор занимает 25–45 c, поэтому:

* `/api/snapshot` никогда не ждёт модель — отдаёт рынок и готовые разборы;
* фронтенд догружает разборы по одному, начиная с выбранного токена;
* бот на `/list` берёт сводку (одна генерация), разборы токенов — по кнопке.

Первое наполнение списка из шести токенов — примерно 4–5 минут генерации,
дальше всё берётся из кэша.
